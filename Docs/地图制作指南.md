## 1. Tilemap 层命名约定

场景中所有 Tilemap 层的名称决定提取器如何解析。以下是各层的命名约定（按优先级匹配，名称不区分大小写）：

| Tilemap 层名 | 必须 | 用途 |
|---|---|---|
| `Base` 或 `Layer0` | ✅ | 基础地形，定义网格尺寸 |
| `PlayerSpawn` 或 `PlayerStart` | ❌ | 玩家出生点标记 |
| `Goal` 或 `VictoryPoint` | ❌ | 目标点标记（供 ReachGoal 条件使用） |
| `WinCondition` 或 `VictoryCondition` | ❌ | 胜利条件配置 |
| `RoundX`（如 `Round1`、`Round2`） | ❌ | 第 X 回合的预设行动 |

### 场景层级结构建议

```
├── Grid（GridManager）
│   ├── Base Tilemap         ← 基础地形
│   ├── PlayerSpawn Tilemap  ← 出生点
│   ├── Goal Tilemap         ← 目标点
│   ├── WinCondition Tilemap ← 胜利条件
│   ├── Round1 Tilemap       ← 第1回合行动
│   ├── Round2 Tilemap       ← 第2回合行动
│   └── ...
├── Units（运行时动态生成）
├── UI（Canvas）
└── Managers（GridManager、LevelManager、TurnManager 等）
```

## 2. 地形绘制

### 创建地形 Tile 资产

1. 在 Project 窗口右键 → `Create` → `Tiles` → `TerrainTile`
2. 设置：

| 字段 | 说明 |
|---|---|
| `Terrain Type` | 地形类型（`ground`=可行走, `unreachable`=不可行走） |
| `Height` | 高度值（影响寻路和逻辑，0=平地） |
| `Preview Sprite` | 编辑器预览用的精灵 |

建议按地形类型分别创建 Tile 资产，例如：
- `Ground_Tile`（TerrainType=ground, height=0）
- `Wall_Tile`（TerrainType=unreachable, height=0）
- `HighGround_Tile`（TerrainType=ground, height=1）

### 绘制地形

1. 选中 `Base` Tilemap 层
2. 打开 Tile Palette（Window → 2D → Tile Palette）
3. 加载或新建 Palette
4. 选中地形 Tile 资产，用刷子工具绘制

**注意**：`Base` 层决定了网格的边界（`cellBounds`），所有其他 Tilemap 层的位置都会相对于此网格计算。提取前请确保 `Base` 层已覆盖完整区域。

## 3. 关卡数据结构

提取操作会自动生成以下资产到 `Assets/ScriptableObjects/LevelData/`：

```
Assets/ScriptableObjects/LevelData/
├── [SceneName].asset              ← 主 LevelData
├── GridData/
│   └── [SceneName]_Grid.asset     ← LevelGridData
└── TurnData/
    └── [SceneName]_Turns.asset    ← LevelTurnData
```

### LevelData 主资产字段

| 字段 | 来源 | 说明 |
|---|---|---|
| `Grid Data` | 自动 | 引用生成的 LevelGridData |
| `Turn Data` | 自动 | 引用生成的 LevelTurnData |
| `Player Spawn Positions` | 自动 | 从 PlayerSpawn Tilemap 提取 |
| `Goal Positions` | 自动 | 从 Goal Tilemap 提取 |
| `Root Condition` | 自动/手动 | 胜利条件根节点 |

## 4. 回合行动配置

在名称为 `RoundX`（如 `Round1`）的 Tilemap 层上放置行动 Tile，提取器会自动解析为 `LevelTurnData`。

### 支持的 Tile 类型

| Tile 类型 | 对应行动 | 说明 |
|---|---|---|
| `SpawnUnitTile` | `SpawnUnitAction` | 在格子生成单位 |
| `CellChangeTile` | `CellChangeAction` | 改变格子地形 |
| `EffectApplyTile` | `EffectApplyAction` | 在格子应用效果 |

### SpawnUnitTile

用于配置某回合在指定位置生成敌人。

需要配置的参数：

| 字段 | 说明 |
|---|---|
| `Spawn Group` | 随机生成池（可选） |
| `Fallback Unit Config` | 兜底单位配置 |
| `Faction Override` | 阵营覆盖 |
| `Use Config Faction` | 是否使用配置中的阵营 |
| `Count` | 生成数量 |
| `Search Range` | 出生点被占用时的搜索半径 |

### CellChangeTile

用于配置某回合格子地形变化（如桥升起、道路坍塌）。

| 字段 | 说明 |
|---|---|
| `Target Terrain` | 目标地形类型 |
| `Set Height` | 是否修改高度 |
| `New Height` | 新的高度值 |
| `Set Walkable` | 是否修改可行走属性 |

### 提取规则

- 每个 `RoundX` Tilemap 对应一个回合，X 为回合编号
- Tilemap 上的每个 Tile 对应一个行动
- 行动的执行顺序为 Tilemap 的 tile 遍历顺序

## 5. 玩家出生点

### 创建 PlayerSpawnTile

1. 在 Project 窗口右键 → `Create` → `Tiles` → `PlayerSpawnTile`
2. 设置 `Preview Sprite` 为可视化的标记精灵

### 绘制出生点

1. 选中 `PlayerSpawn` Tilemap 层
2. 用 `PlayerSpawnTile` 在需要的位置标记出生点

**注意**：
- 多个出生点时，玩家阵容会随机分配到这些位置
- 出生点数量应>=玩家阵容数量，多余的出场单位会被忽略
- 出战阵容由 `SaveManager` 的存档决定，当前为阵容列表

## 6. 胜利条件配置

在 `WinCondition` Tilemap 层上放置条件 Tile 来配置胜利条件。

### 规则

- **同一 y 坐标** = AND 组合
- **不同 y 坐标** = OR 组合
- **相同 Tile 的数量** = 数值参数（如存活回合数）

### 可用条件 Tile

| Tile 类型 | 数量含义 | 说明 |
|---|---|---|
| `KillAllEnemiesTile` | 忽略（标记） | 全歼所有敌方单位 |
| `SurviveRoundsTile` | 数量 = 需要存活的回合数 | 坚守指定回合 |
| `ProtectUnitTile` | 忽略，`targetUnitId`需手动编辑 | 保护指定单位 |
| `ReachGoalTile` | 忽略（标记） | 任意单位到达 Goal 位置 |

### 配置示例

目标：**通关条件 = 到达目标点 OR（全歼敌人 AND 存活 5 回合）**

在 `WinCondition` 层绘制：

```
y=2: [ReachGoal]                    → OR: ReachGoal
y=1: [KillAllEnemies]               → AND:
y=0: [Survive][Survive][Survive]
     [Survive][Survive]             → SurviveRounds(5)
```

提取后自动生成：

```
rootCondition (OR)
├─ ReachGoal
└─ CompositeCondition (AND)
    ├─ KillAllEnemies
    └─ SurviveRounds(5)
```

### 手动编辑非数值参数

对于 `ProtectUnitTile`，`targetUnitId` 需要提取后手动设置：

1. 在 `WinCondition` 层放置 1 个 `ProtectUnitTile`
2. 运行提取器 → 生成 `ProtectUnitCondition { targetUnitId = "" }`
3. 打开生成的 `LevelData` 资产，展开 `Root Condition`，填入目标单位的 `Unit ID`

## 7. 目标点

`ReachGoalCondition` 引用的是 `Goal` Tilemap 层上的位置，而不是 `WinCondition` 层。

### 配置步骤

1. 新建 `Goal` Tilemap 层
2. 创建 `GoalTile` 资产（Project 右键 → Create → Tiles → GoalTile）
3. 在 `Goal` 层上放置 `GoalTile` 标记目标位置

提取器会自动将这些位置写入 `LevelData.goalPositions`。

## 8. 提取关卡数据

完成所有 Tilemap 绘制后：

1. 保存场景
2. 菜单栏 → `Tools` → `Extract LevelData From Scene`
3. 如果已存在同名 `LevelData`，会提示是否覆盖

提取成功后弹出提示，显示生成的资产路径和统计数据：

```
已生成以下资产：
主关卡：Assets/ScriptableObjects/LevelData/[SceneName].asset
地形网格：... ([宽]x[高])
回合事件：... ([N] 个回合)
玩家出生点：[N] 个
```

提取后建议检查：
- 打开生成的 `LevelData` 资产
- 确认 `Grid Data` 和 `Turn Data` 引用正确
- 检查 `Root Condition` 结构是否正确
- 如有 `ProtectUnitCondition`，手动填入 `targetUnitId`

## 9. 测试

### 场景中需存在的管理器

| 管理器 | 说明 |
|---|---|
| `GridManager` | 必须，带 Grid 组件 |
| `LevelManager` | 必须，负责关卡初始化 |
| `TurnManager` | 必须，管理回合流程 |
| `AsyncEffectExecutor` | 必须，执行卡牌效果链 |
| `VictoryChecker` | 推荐，检查胜利条件 |
| `AIController` | 敌人 AI 需要 |
| `DeckManager` | 卡牌系统需要 |
| `HandUI` | 手牌显示需要 |
| `ResourceManager` | 资源管理需要 |
| `SaveManager` | 存档需要 |

### 快速测试流程

1. 确保场景中有 `GridManager` + `LevelManager`
2. 确保 `LevelManager` 引用了正确的 `LevelData`
3. 运行场景，观察：
   - 网格是否正确加载
   - 玩家单位是否在出生点生成
   - 回合行动是否按预期触发
   - 胜利条件是否在适当时机触发

## 10. 常见问题

### Q: 提取时提示"未找到名为 'Base' 或 'Layer0' 的 Tilemap"

确保场景中有一个名称为 `Base` 或 `Layer0` 的 Tilemap 层作为基础地形。

### Q: 玩家单位没有生成

- 检查 `PlayerSpawn` Tilemap 层是否存在并放置了 `PlayerSpawnTile`
- 检查 `SaveManager` 是否有玩家阵容数据
- 检查阵容中的 `UnitConfig.unitPrefab` 是否已赋值

### Q: 胜利条件没有触发

- 确认 `VictoryChecker` 在场景中
- 确认 `LevelManager.Initialize` 时输出了 `VictoryChecker` 初始化日志
- 检查 `LevelData.rootCondition` 是否有值
- 需要单位死亡的场景：确认 `KillAllEnemiesCondition` 是否匹配正确的 `Faction`

### Q: 回合行动没有执行

- 确认 `LevelTurnData` 中有对应回合的 `RoundActions`
- 确认 `SpawnUnitAction` 的 `fallbackUnitConfig` 有值
- 确认 `Round` Tilemap 的名称格式正确（如 `Round1`）

### Q: 提取后 `ReachGoalCondition` 不生效

- 确认 `Goal` Tilemap 层存在并放置了 `GoalTile`
- 提取后检查 `LevelData.goalPositions` 是否有坐标数据
