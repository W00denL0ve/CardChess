数据与表现分离的设计

---

## 一、总体设计思路

1. **数据层**：`LevelData`（ScriptableObject）存储关卡的静态网格数据（每个格子的逻辑属性）。  
2. **编辑层**：利用 Unity Tilemap 编辑器 + 自定义 `TileBase` 来配置每个格子的数据，然后通过编辑器脚本导出为 `LevelData` 资产。  
3. **运行层**：`GridManager` 在 Boot 阶段常驻，进入关卡时加载 `LevelData`，初始化内部的逻辑网格 `Cell[,]`，并根据数据动态生成可视化立方体（每个格子一个半透明薄片）。

这样做的好处：

- Tilemap 只在编辑时使用，游戏运行时完全不依赖 Tilemap 和 Tile 资产。
- 可视化与逻辑分离，可随时更换表现样式（如换材质、缩放）。
- 每个格子独立 Cube，通过调整大小留出缝隙自然形成网格线，无需额外边框。

## 二、定义逻辑数据载体

### 1. `CellData` 结构体（挂载在 `LevelData` 中）

```csharp
[System.Serializable]
public struct CellData
{
    public bool isWalkable;   // 是否可行走
    public int moveCost;      // 移动消耗
    // 可扩展：地形类型ID、防御加成、特效ID等
}
```

### 2. `LevelData` ScriptableObject

```csharp
using UnityEngine;

[CreateAssetMenu(fileName = "LevelData", menuName = "Game/LevelData")]
public class LevelData : ScriptableObject
{
    public int width;          // 网格宽（列数）
    public int height;         // 网格高（行数）
    public CellData[] cells;   // 一维数组，存储顺序为 x + y * width

    public CellData GetCell(int x, int z)
    {
        int index = z * width + x;
        return cells[index];
    }

    // 编辑器专用：填充数据
    public void SetGridData(int w, int h, CellData[] data)
    {
        width = w;
        height = h;
        cells = data;
    }
}
```

## 三、编辑器阶段：Tilemap 绘制并导出数据

### 1. 自定义 Tile（`TerrainTile`）

继承 `TileBase`，并在 Inspector 中暴露逻辑字段，方便绘制时设置。

```csharp
using UnityEngine;
using UnityEngine.Tilemaps;

[CreateAssetMenu(fileName = "TerrainTile", menuName = "Tiles/TerrainTile")]
public class TerrainTile : TileBase
{
    public bool isWalkable = true;
    public int moveCost = 1;
    // 可扩展其他字段

    public override void GetTileData(Vector3Int position, ITilemap tilemap, ref TileData tileData)
    {
        // 只需要返回一个预览用的 Sprite（可选）
        // 若完全不需要视觉表现，可留空
        tileData.sprite = null;
    }
}
```

### 2. 导出器 `LevelDataExtractor`（编辑器脚本）

放在 `Editor` 文件夹下，在 Inspector 中一键提取数据到 `LevelData` 资产。

```csharp
using UnityEngine;
using UnityEngine.Tilemaps;
using UnityEditor;

public class LevelDataExtractor : MonoBehaviour
{
    public Tilemap tilemap;          // 绘制好的 Tilemap
    public LevelData targetData;     // 要导出的 LevelData 资产

    [ContextMenu("Extract to LevelData")]
    public void Extract()
    {
        BoundsInt bounds = tilemap.cellBounds;
        int width = bounds.size.x;
        int height = bounds.size.y;
        CellData[] cells = new CellData[width * height];

        for (int x = 0; x < width; x++)
        {
            for (int y = 0; y < height; y++)
            {
                Vector3Int pos = new Vector3Int(bounds.xMin + x, bounds.yMin + y, 0);
                TerrainTile tile = tilemap.GetTile<TerrainTile>(pos);
                if (tile != null)
                {
                    cells[y * width + x] = new CellData
                    {
                        isWalkable = tile.isWalkable,
                        moveCost = tile.moveCost
                    };
                }
                else
                {
                    // 无 Tile 的格子默认为不可行走
                    cells[y * width + x] = new CellData { isWalkable = false, moveCost = 0 };
                }
            }
        }

        targetData.SetGridData(width, height, cells);
        EditorUtility.SetDirty(targetData);
        AssetDatabase.SaveAssets();
        Debug.Log("导出完成");
    }
}
```

**使用流程**：

- 在编辑场景中放置 `Grid` + `Tilemap`，用 `TerrainTile` 资产绘制地形。
- 创建一个空物体，挂载 `LevelDataExtractor`，拖入 `Tilemap` 和目标 `LevelData` 资产。
- 右键组件 → `Extract to LevelData`，完成导出。

## 四、运行时：GridManager 加载数据并生成可视化

### 1. `GridManager` 核心逻辑

```csharp
using System.Collections.Generic;
using UnityEngine;

public class GridManager : MonoBehaviour
{
    public static GridManager Instance { get; private set; }

    [Header("Visual Settings")]
    public GameObject cellVisualPrefab;   // 半透明立方体预制体
    public float visualScaleFactor = 0.9f; // 立方体大小比例（小于1留缝隙）
    public float visualHeight = 0.1f;      // 立方体厚度

    private Cell[,] grid;           // 逻辑网格
    private LevelData currentLevel;

    void Awake()
    {
        if (Instance == null) Instance = this;
        else Destroy(gameObject);
        DontDestroyOnLoad(gameObject);
    }

    // 进入关卡时调用，传入从 Resources 或 AssetBundle 加载的 LevelData
    public void LoadLevel(LevelData levelData)
    {
        currentLevel = levelData;
        InitializeGrid(levelData);
        GenerateVisuals();
    }

    private void InitializeGrid(LevelData data)
    {
        int w = data.width, h = data.height;
        grid = new Cell[w, h];
        for (int x = 0; x < w; x++)
        {
            for (int z = 0; z < h; z++)
            {
                CellData cellData = data.GetCell(x, z);
                grid[x, z] = new Cell
                {
                    coord = new Vector2Int(x, z),
                    isWalkable = cellData.isWalkable,
                    moveCost = cellData.moveCost
                };
            }
        }
    }

    private void GenerateVisuals()
    {
        // 清除旧的视觉物体（如果有）
        foreach (Transform child in transform) Destroy(child.gameObject);

        float cellSize = 5f; // 根据你的项目设定，比如每个格子世界单位长度为5
        float visualSize = cellSize * visualScaleFactor;
        Vector3 cubeScale = new Vector3(visualSize, visualHeight, visualSize);

        for (int x = 0; x < currentLevel.width; x++)
        {
            for (int z = 0; z < currentLevel.height; z++)
            {
                Vector3 worldPos = GetWorldPosition(x, z, cellSize);
                GameObject cube = Instantiate(cellVisualPrefab, worldPos, Quaternion.identity, transform);
                cube.transform.localScale = cubeScale;
                // 可选：根据地形类型改变颜色或材质
                // cube.GetComponent<Renderer>().material.color = ...;
            }
        }
    }

    // 根据格子坐标计算世界坐标（假设格子中心在整数倍 cellSize 上）
    public Vector3 GetWorldPosition(int x, int z, float cellSize = 5f)
    {
        return new Vector3(x * cellSize, 0, z * cellSize);
    }

    // 公共接口：获取格子逻辑数据
    public Cell GetCell(int x, int z)
    {
        if (x >= 0 && x < currentLevel.width && z >= 0 && z < currentLevel.height)
            return grid[x, z];
        return null;
    }

    // 其他方法（GetAdjacentCells, GetMovableCells...）保持不变，但需基于 grid 数组
}

// 运行时格子逻辑类
public class Cell
{
    public Vector2Int coord;
    public bool isWalkable;
    public int moveCost;
    // 可扩展 occupant 等
}
```

### 2. 半透明立方体预制体

- 创建一个 Cube，移除 `Collider`（点击检测另外用射线）。
- 材质：使用 `Standard` 或 `Unlit/Color`，设置颜色（如淡蓝色），`Alpha` 设为 0.3~0.5，并勾选 `Render Face` 为 `Both`（可选）。
- 将预制体拖入 `cellVisualPrefab` 字段。

## 五、完整工作流

1. **数据配置**  
   
   - 创建 `TerrainTile` 资产（例如草地、森林、水），设置每个 Tile 的 `isWalkable` 和 `moveCost`。  
   - 在 Tile Palette 中用这些 Tile 在 Tilemap 上绘制关卡。

2. **数据导出**  
   
   - 创建 `LevelData` 资产（右键 → Create → Game → LevelData）。  
   - 在场景中放置 `LevelDataExtractor`，拖入 Tilemap 和 `LevelData` 资产，执行提取。  
   - 导出后，`LevelData` 资产即包含完整的逻辑网格数据。

3. **运行时加载**  
   
   - Boot 场景中已有 `GridManager`（单例常驻）。  
   - 进入关卡时，根据关卡 ID 加载对应的 `LevelData`（如 `Resources.Load<LevelData>("Levels/Level_01")`）。  
   - 调用 `GridManager.Instance.LoadLevel(levelData)`，自动生成半透明立方体可视化。

4. **交互与逻辑**  
   
   - 射线检测到立方体时，通过 `GetGridCoord` 找到对应逻辑格子，后续移动、寻路等均使用 `GridManager` 的接口。

## 六、优势总结

- **完全分离**：Tilemap 只在编辑器中使用，游戏包体不含 Tilemap 和 Tile 资产，只含 `LevelData` 和视觉预制体。  
- **可视化清晰**：每个格子独立的半透明立方体，通过 `visualScaleFactor` 控制间隙，自然呈现网格线，无需额外边框。  
- **高性能**：运行时没有复杂的 Mesh 合并，每个格子一个 GameObject 对于中小地图（例如 30x30）完全可接受。若需要大型地图，可优化为合并 Mesh。  
- **易扩展**：`CellData` 可增加任意字段（地形类型、特效 ID 等），编辑器 Tile 中对应增加字段，导出后即可在运行时使用。

按照这个方案，你可以完全抛弃之前复杂的边框 Mesh 合并，获得更直观、易维护的可视化系统。


## 分析你的多 Tilemap 分层新思路

你的想法是**将多个 Tilemap 用于存储不同回合的关卡事件**，而将格子的基础地形信息（类型、高度）集中到第 0 层（Layer0），后续 Layer1、Layer2… 分别对应第 1 回合、第 2 回合……，在其中标记“敌人出现位置”“格子状态变化”等事件。

这个用法**非常有创意，且完全可行**，它能将回合制脚本化的内容可视化、直观编辑，非常适合你的卡牌+战棋游戏。

---

### 一、优势

- **可视化编辑**：每个回合的地图变化、敌人生成位置一眼可见，便于设计和调试。
- **与回合机制天然契合**：TurnManager 推进到第 N 回合时，直接读取第 N 层数据执行事件。
- **数据与表现分离依然保持**：Tilemap 仅用于编辑，运行时所有数据均转换为独立的结构，不依赖 Tilemap。
- **扩展容易**：新事件类型只需定义新的 `Tile`（如 `EnemySpawnTile`、`EffectTile` 等），在导出工具中解析即可。

---

### 二、可能的问题与优化建议

| 问题 | 优化建议 |
|------|----------|
| **每回合一个 Tilemap，大量回合时层数过多** | 只对**有事件的回合**创建 Tilemap（例如只有回合 1、3、5 有事件，则只有 Layer1、Layer3、Layer5），其余回合不创建，导出时自动跳过。 |
| **每层仍是完整的 width×height 网格，数据冗余** | 导出时可以不导出整个网格，而是**仅导出有 Tile 的格子**，运行时作为稀疏事件列表存储。 |
| **事件类型有限（敌人、格子变化、其他）** | 可以创建多个 `TerrainTile` 的派生类或不同 Tile 资产，例如 `EnemySpawnTile`（包含敌人 ID）、`EventTile`（包含事件类型枚举），在导出器中根据 Tile 类型生成不同的事件数据。 |
| **运行时如何应用事件** | `LevelManager` 加载 LevelData 后，预解析所有回合事件到 `Dictionary<int, List<TurnEvent>>`（键为回合数），在 `TurnManager` 每回合开始时，由 `LevelManager` 执行该回合事件列表。 |

---

### 三、推荐的数据结构设计

**将原有的 `LayerData` 改为 `TurnEventLayer` 的概念：**

```csharp
// 事件基类
[System.Serializable]
public abstract class TurnEvent
{
    public Vector2Int coord; // 发生在哪个格子
}

// 示例：敌人生成事件
[System.Serializable]
public class EnemySpawnEvent : TurnEvent
{
    public string enemyPrefabId; // 或 enemy 配置 ID
    public int count;
}

// 示例：格子状态变化事件
[System.Serializable]
public class CellChangeEvent : TurnEvent
{
    public TerrainType newTerrainType;
    public int newHeight;
    public bool setWalkable;
}

// LevelData 中存储
public class LevelData : ScriptableObject
{
    public int width;
    public int height;
    public CellData[] baseGrid; // 第0层：基础格子数据

    // 所有回合事件，按回合数分组，稀疏存储
    public List<TurnEventsByRound> roundEvents = new List<TurnEventsByRound>();
}

[System.Serializable]
public class TurnEventsByRound
{
    public int round;                  // 回合数（1, 2, 3…）
    public List<TurnEvent> events;     // 该回合所有事件
}
```

这样运行时加载的数据体积很小，不需要每个回合存储完整网格。

### 四、编辑器工具修改思路

1. **命名约定**：要求 Tilemap 名称包含 `Round` 关键字和数字，例如 `Round1`、`Round2_Enemies` 等。导出工具根据名称解析回合数。
2. **导出流程**：
   - 获取名为 `Layer0` 或 `Base` 的 Tilemap → 提取基础网格数据（所有格子的 terrainType、height）。
   - 遍历其他名称匹配 `RoundN` 的 Tilemap：
     - 对每个格子，获取 Tile，如果是特定的 `EventTile` 或 `EnemySpawnTile`，则根据 Tile 类型创建 `TurnEvent` 实例，加入该回合的事件列表。
   - 组装 `LevelData`。
3. **Tile 资产设计**：
   - 基础地形仍用 `TerrainTile`（包含 terrainType、height）。
   - 事件 Tile 新建：`EnemySpawnTile`（包含敌人 ID）、`CellChangeTile`（包含新地形、高度等）。
   - 可都继承自 `TileBase`，导出时用 `is` 或类型判断。

### 五、运行时集成

在 `LevelManager.Initialize(LevelData levelData)` 中：

```csharp
public class LevelManager : MonoBehaviour
{
    private LevelData levelData;
    private Dictionary<int, List<TurnEvent>> eventMap = new Dictionary<int, List<TurnEvent>>();

    public void Initialize(LevelData data)
    {
        this.levelData = data;
        // 初始化基础网格
        GridManager.Instance.LoadLevel(data.width, data.height, data.baseGrid);
        gridVisualizer.RebuildAllVisuals();

        // 构建回合事件字典
        foreach (var round in data.roundEvents)
        {
            eventMap[round.round] = round.events;
        }

        // 开始游戏
        turnManager.OnTurnStart += ApplyRoundEvents;
        turnManager.StartTurn();
    }

    void ApplyRoundEvents(int roundNumber)
    {
        if (eventMap.TryGetValue(roundNumber, out var events))
        {
            foreach (var e in events)
            {
                if (e is EnemySpawnEvent spawn)
                    SpawnEnemy(spawn);
                else if (e is CellChangeEvent change)
                    ApplyCellChange(change);
                // 其他事件...
            }
        }
    }
}
```

### 六、总结

你的想法将 Tilemap 的“层”从静态地形分层转变为动态回合事件层，**非常适合回合制战棋的关卡设计**。通过稀疏存储、事件抽象和合理的编辑器约定，能够既保持编辑的直观性，又不会造成数据冗余或运行时性能问题。

**需要调整的部分**：  
- 扩展 `LevelData` 结构，增加基础网格和回合事件列表。  
- 设计事件类体系（`TurnEvent` 基类 + 多种事件子类）。  
- 修改导出工具以解析不同 Tile 类型并生成对应事件数据。  
- `LevelManager` 负责在回合切换时执行事件。

这个方案完全可行，且与你已有的 `TurnManager`、`GridManager` 架构完美契合。如果你愿意，我可以进一步提供导出工具中解析事件 Tile 的详细代码实现。
