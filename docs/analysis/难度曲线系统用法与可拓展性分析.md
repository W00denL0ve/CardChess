## 难度曲线系统 — 用法与可拓展性分析

---

## 一、完整用法

### 1. 创建资产

在 Project 窗口右键：
```
Create → Game → Difficulty → DifficultyConfig          → 命名 "Forest_Difficulty"
Create → Game → Difficulty → DifficultyConfig          → 命名 "Cave_Difficulty"
Create → Game → Unit → SpawnGroup                        → 命名 "GoblinCamp"
Create → Game → Unit → SpawnGroup                        → 命名 "UndeadCrypt"
```

### 2. 配置 SpawnGroup

```
SpawnGroup_GoblinCamp
├── Entries:
│   ├── unitConfig: Goblin        rarity: Common   weight: 6
│   ├── unitConfig: GoblinArcher  rarity: Common   weight: 4
│   ├── unitConfig: GoblinShaman  rarity: Uncommon weight: 3
│   └── unitConfig: GoblinBoss    rarity: Rare     weight: 1
```

### 3. 配置 DifficultyConfig

打开 `Forest_Difficulty.asset`，Inspector 中会看到 4 条曲线：

**推荐初始曲线形状：**

| 稀有度 | 曲线行为 | X=0 | X=1 | X=2 | X=3 |
|---|---|---|---|---|---|
| **Common** | 常量 1 | 1.0 | 1.0 | 1.0 | 1.0 |
| **Uncommon** | 缓慢上升 | 1.0 | 1.2 | 1.5 | 2.0 |
| **Rare** | 从 0 起步，中后期上升 | **0.0** | 0.5 | 1.5 | 3.0 |
| **Elite** | 后期解锁 | **0.0** | **0.0** | 1.0 | 3.0 |

门槛设置：
```
Rare Min Difficulty:  0.5
Elite Min Difficulty: 1.5
```

### 4. 配置 UnitSpawnTile

```
UnitSpawnTile 资产
├── Spawn Group:   GoblinCamp          ← 引用 SpawnGroup
├── Fallback:      Goblin              ← 兜底
├── Allowed Terrains: [ground]
└── Search Range:  3
```

### 5. 运行时接入

**地图加载时**设置难度曲线：

```csharp
// LevelManager 或 MapManager 中
void LoadMap(MapData mapData)
{
    TurnActionExecutor.CurrentDifficulty = mapData.difficultyConfig;
    // ... 加载地图、设置波次等
}
```

**每波生成前**计算综合难度值：

```csharp
float GetCurrentDifficulty()
{
    // baseDifficulty 取自地图配置
    // stageIndex 当前是第几波（从 0 开始）
    // totalStages 本图总波数
    // stageRange  波次对应的难度跨度（例如 2.5）
    return baseDifficulty + (stageIndex / totalStages) * stageRange;
}
```

实际落到 `TurnActionExecutor.GetCurrentDifficulty()` 中。

### 6. 执行流程（完整链路）

```
地图加载
  └─ TurnActionExecutor.CurrentDifficulty = Forest_Difficulty
  └─ roundNumber = 0

第 2 轮，第 2 波：
  stageIndex = 1, totalStages = 6, baseDifficulty = 0.5, stageRange = 2.5
  → difficulty = 0.5 + (1/6) * 2.5 = 0.92

SpawnUnitTile_Camp → SpawnUnitAction
  → ResolveUnitConfig()
    → spawnGroup.PickUnit(0.92, Forest_Difficulty)
      ├─ Common:   6 × 1.0  = 6.0     (weight × curve.Evaluate(0.92))
      ├─ Common:   4 × 1.0  = 4.0
      ├─ Uncommon: 3 × 1.2  = 3.6
      └─ Rare:     1 × 0.46 = 0.46    (curve ≈ 0.46 at X=0.92)
      → 加权随机池: 总权重 ≈ 14.06
      → 结果: GoblinArcher  ← 随机抽取

  → FindSpawnPosition()
    → 格子可用 → 直接生成
    → 被占用 → 曼哈顿范围 3 内搜索最近可用格子
```

## 二、可拓展性分析

### ✅ 已支持的拓展点

| 场景 | 如何实现 | 改动量 |
|---|---|---|
| **新增稀有度** | 在 `RarityTier` 加一个枚举值，`DifficultyConfig` 加一条曲线 | 2 行 + 1 条 Inspector 曲线 |
| **不同地图不同曲线** | 创建不同的 `DifficultyConfig` 资产，地图数据里引用 | 0 行代码 |
| **同一地图内分段曲线** | 拆成多个 `DifficultyConfig`，按回合切换 | 调用方加个 if |
| **单位解锁条件** | 在 `WeightedEntry` 加 `minFloor`/`maxFloor` | `SpawnGroup.PickUnit` 加一行过滤 |
| **事件/天气临时调难度** | 在 `GetCurrentDifficulty()` 返回值上加临时修正值 | 1 行 |
| **Boss 房独立曲线** | 创建专门的 `Boss_Difficulty`，Boss 回合切换引用 | 0 行代码 |

### 🟡 需要注意的局限

| 局限 | 说明 | 可接受的替代方案 |
|---|---|---|
| **曲线是全局的** | 所有 SpawnGroup 共享同一个 `DifficultyConfig` 的曲线形状 | 如果你需要不同种族有不同的难度曲线（比如哥布林精英出现得早，亡灵精英出现得晚），可以为每个种族创建不同的 `DifficultyConfig`，SpawnGroup 里各自引用 |
| **抽取是独立的** | 每次 `PickUnit` 只知道自己的池，不知道场上已经有多少怪 | 如果需要"已经出了 3 个精英就不再出精英"这样的保底机制，需要在 `SpawnGroup` 上加状态或外挂一个全局计数器 |
| **权重不保存运行时状态** | 不记录上次抽了什么 | 需要"不连续抽同一个单位"这样的约束，需要在 `SpawnGroup` 上加临时黑名单机制 |

### 🔧 未来可以轻松添加的增强

```csharp
// 在 WeightedEntry 上加楼层限制
public int minFloor;
public int maxFloor;

// 在 SpawnGroup 上加"最近不重复"机制
private UnitConfig lastPicked;

// 在 TurnActionExecutor 上加全局"精英上限"
public static int MaxEliteOnField = 3;
```

---

### 一句话总结

这套系统的核心价值是：**改一个 `DifficultyConfig.asset` 就能调控整局游戏的怪物构成，不需要碰任何 `SpawnGroup`、`Tile`、或代码**。绝大多数后续需求都可以通过"加一条曲线 / 加一个字段"的方式零散拓展，不需要重构。
